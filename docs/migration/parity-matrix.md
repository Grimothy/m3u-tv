# Flutter Implementation Status

The React Native / Electron app has been fully removed. The Flutter app at `flutter_client/` is the only active TV frontend. This matrix tracks what is implemented, what remains pending, and what is gated/blocked.

Legend: **Done** = implemented in Flutter, **Partial** = partially implemented or player-dependent, **Gap** = not yet implemented, **Gated** = implementation complete but release gated on signing/platform work, **Blocked** = dependency missing (e.g., no Flutter tvOS embedder).

## Playback backend status

| Backend | Status | Applies to |
| --- | --- | --- |
| ExoPlayer (Media3) | Primary Android backend, mpv the automatic fallback (see the platform row above). Handles H.264, H.265, AV1, AC3 (passthrough), HLS, MPEG-TS, MP4. Renders via `m3u_tv/android_exo_view`, a Hybrid Composition `PlatformView` hosting a real `SurfaceView` (`Media3PlaybackPlugin.kt`) -- not a Flutter texture, which was found to break HDR dataspace negotiation (red picture) and add jitter on real Shield hardware. Sideloaded subtitles (`PlaybackSource.externalSubtitles`) are added as `MediaItem.SubtitleConfiguration`s (SRT/VTT/TTML/SSA mime-typed by file extension) alongside whatever's embedded in the container -- basic formats only, no advanced subtitle rendering. | Android, Android TV. |
| MPV/libmpv Android | Automatic **fallback** playback path (`androidMpv`, `dev.jdtech.mpv` libmpv bindings via a `SurfaceView`-hosted `AndroidView`) for streams ExoPlayer can't handle (advanced codecs, external subtitles, advanced subtitle formats); confirmed via limited manual testing on physical Android TV hardware (playback starts, video renders, clean back-navigation teardown); broader codec/device QA still open. | Android, Android TV. |
| MPVKit native mpv (Apple) | Active primary backend on iOS/iPadOS/tvOS/macOS (`edde746/MPVKit`, `appleMpvNative`/`macMpvNative`), confirmed working via click-testing on macOS/iOS and playback verification on tvOS. GPL-3.0 relicense (repo root `LICENSE`) unblocked App Store distribution for this. The tvOS overlay-scaling cosmetic bug has been fixed. | iOS, iPadOS, macOS, tvOS. |
| AVKit/AVPlayer | Automatic fallback if native mpv throws a recoverable exception, on iOS/iPadOS/tvOS only. macOS currently has no automatic native fallback. | iOS, iPadOS, tvOS. |
| media_kit Apple | Removed entirely, including from the macOS Multiview surface: `buildMultiviewTilePlayer()` now uses `MacMpvNativeBackend` (which implements `MultiviewBackend`) instead of `MediaKitDesktopAdapter`. No longer used anywhere on macOS or iOS. | None (retired). |
| media_kit Linux/Windows | Removed entirely (not just left unregistered): `media_kit`/`media_kit_video`/`media_kit_libs_linux`/`media_kit_libs_windows_video` are no longer dependencies at all. `MediaKitDesktopAdapter` was never actually registered as a fallback in `buildPlaybackOrchestrator()` for desktop, and on Windows the vendored `libmpv-2.dll` it bundled collided (same filename, same output directory) with this project's own fetched gpu-next/D3D11-capable build, silently overwriting it and reproducing a VO-open failure -- see the "Honest Release Blockers" entry in `docs/release/platform-release-matrix.md`. | None (retired). |
| libmpv desktop | Active for Linux/Windows only, GPU-rendered on both (ANGLE-backed GPU texture on Windows, Wayland `wl_subsurface` on Linux, both with SW-path fallback), confirmed on real hardware; gated on release-packaging work (signing, bundled runtime licensing). Not used on macOS, which now uses native mpv via MPVKit instead. | Linux, Windows. |
| Server transcode | Final fallback for all platforms when direct playback fails. Contract defined in `m3u-editor-transcoding-contract.md`. | All platforms. |

## Direct M3U requirements (pending)

Direct M3U support is not present in the Flutter app (it was also absent from the RN app). When implemented it must:

- Accept `#EXTM3U` playlists and tolerate malformed entries without crashing.
- Parse `#EXTINF` display names plus attributes: `tvg-id`, `tvg-name`, `tvg-logo`, and `group-title`.
- Treat the following non-comment line after `#EXTINF` as the stream URL.
- Preserve or normalize custom headers/user-agent metadata for playback backends that support them.
- Group channels by `group-title`, with an All Channels view and stable grouping for missing groups.
- Map EPG data by `tvg-id` first, then `tvg-name`/display-name fallback.
